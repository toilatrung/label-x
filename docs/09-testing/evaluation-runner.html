OPS-01: trusted evaluation runner (#388)

This PR provides an executable service probe and operating procedure. Registration, online runner state, protected environment settings and an actual Phase Testing run remain NOT VERIFIED until an authorized operator supplies evidence. Local tests do not prove those external conditions.

Install and access

  1. Allocate a dedicated Linux evaluation host with no production network route, production credentials or shared production Docker socket. Use a dedicated unprivileged service account, encrypted local storage and restricted maintainer SSH access. Docker socket membership is root-equivalent; restrict it to the operator if containers are provisioned separately.
  2. Install a supported GitHub Actions runner release from the repository Settings / Actions / Runners page. Record its exact version and verify the published SHA-256 before unpacking. Generate the short-lived registration token in that page; do not store it in this repository, shell history or artifacts. Register the runner with labels self-hosted,linux,labelx-evaluation and run it as a system service. Only an authorized operator performs registration.
  3. Install Python 3.12, Node 22, uv and gh. Before enabling jobs, record exact patch versions and package/archive SHA-256 in the private host inventory; install from these pinned packages. Run uv sync --frozen --project src/backend; the committed uv lock is the application dependency source. Record python --version, node --version, uv --version, gh --version and runner version with each acceptance run. Do not silently upgrade a host used for baseline comparisons.
  4. Restrict runner group repository access to LabelX. The phase workflow accepts trusted main only; do not enable pull request or fork execution on this host. Protect the labelx-evaluation environment with required reviewers and prevent self-review. The workflow checks protection before tests.

Isolated services and secrets

Provision dedicated PostgreSQL, Redis and S3-compatible storage. Reuse the service/image setup in .github/workflows/ci.yml for disposable local verification, or the existing scoped storage smoke setup in scripts/containers/storage_smoke.py. Do not reuse the development Compose project: its fixed ports and persistent volumes are shared developer data. Pin provisioned images by digest in the host inventory. Keep service listeners on a private network or loopback; allocate unique host ports if needed.

Create a dedicated PostgreSQL database and role with rights to create the pytest test database, no access to other databases. Use a dedicated Redis instance (database numbers alone are not a security boundary). Create the S3 test bucket in advance, grant only that bucket, and deny all production buckets. Use an unversioned disposable bucket or configure lifecycle expiry of noncurrent versions and delete markers. Test deletion on a versioned bucket leaves previous versions for lifecycle cleanup.

Store only evaluation credentials as environment secrets: TEST_DATABASE_URL, TEST_CELERY_BROKER_URL, TEST_CELERY_RESULT_BACKEND, TEST_OBJECT_STORAGE_ENDPOINT_URL, TEST_OBJECT_STORAGE_ACCESS_KEY, TEST_OBJECT_STORAGE_SECRET_KEY, DJANGO_SECRET_KEY. Set TEST_OBJECT_STORAGE_BUCKET as an environment variable. Follow the workflow mapping to unprefixed application variable names. Never print an environment dump, SDK exception, presigned URL, Docker inspect result or raw application logs into public evidence.

Health and data-plane acceptance

Load the unprefixed variables from a private, mode-0600 operator environment file without shell tracing. Explicitly acknowledge isolated service ownership and choose the current run namespace:

export LABELX_EVALUATION_ISOLATED=true
export LABELX_TEST_NAMESPACE=ci-123456-1
uv run --frozen --project src/backend python scripts/ci/evaluation-probe.py

The command returns nonzero for BLOCKED configuration or any failed probe. PostgreSQL performs an insert/read in a temporary table then rolls back. Both Redis URLs perform PING, a unique SET/GET and exact-key DELETE with a 60-second expiry fallback. S3 performs bucket health and PUT/HEAD/GET/DELETE under a unique namespace key, with cleanup attempted on failure. Output contains only check names, statuses and namespace. It never prints exception text or connection information. A cleanup failure fails the probe.

Save this sanitized JSON with commit SHA, run URL, exact tool versions and service image digests. The workflow runs this command as a required step before Phase Testing. After provisioning, the operator must explicitly set the environment variable LABELX_EVALUATION_ISOLATED=true; its absence blocks execution. A PASS probe alone does not validate evaluation policy, reference data or the MVP scenarios.

Cleanup, rotation and updates

  • For disposable runs, stop and delete only resources bearing the exact run-owned project name/labels after artifact export. Do not use global Docker prune, Redis FLUSHDB/FLUSHALL, shared bucket deletion or a broad SQL cleanup. For interrupted jobs, an operator removes only the recorded run namespace and drops only its dedicated pytest database after confirming no active jobs. Configure S3 lifecycle expiry as a crash recovery fallback.
  • Rotate secrets by pausing dispatch, draining active jobs, issuing new scoped test credentials, updating environment secrets, running the probe and a reviewed Phase Testing run, then revoking the old credentials. Restart the runner service if host credentials changed. Never reuse a production access key for evaluation.
  • Update the runner and tools during a drained maintenance window. Verify new archive checksums, update the private inventory pins, run the probe and the frozen-lock suite, and retain previous package pins for rollback. Monitor runner auto-updates; re-baseline inventory whenever a runner version changes.
  • Export only .ci-artifacts/phase-public/ through the existing evidence exporter. Keep raw JUnit, stdout, stderr and private references local with operator-only access and documented retention. Clean the workspace between trusted jobs; use a dedicated host and no untrusted code.
