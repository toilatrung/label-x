#388 — Checklist đăng ký runner labelx-evaluation

Chỉ là tài liệu cho người vận hành. Không có runner nào được đăng ký, không đổi settings repo, secrets hay variables bởi tài liệu này. Việc đăng ký cần người có quyền admin repo và quyền trên máy runner. Bổ sung cho evaluation-runner.html (quy trình vận hành); trạng thái #388 vẫn NOT VERIFIED tới khi có bằng chứng ở mục 8.

0. Vì sao phải là máy riêng

  • Không đặt trên VPS production. Ngân sách RAM của VPS đã sát (đỉnh workload 8.320 MiB + OS/K3s/Argo 3.072 + headroom 1.024 ≈ 12,4 GiB, infrastructure/vps-budget.json); chạy Postgres/Redis/S3 test và pytest cạnh production có thể gây OOM cho pod production. VPS cũng giữ credential production.
  • Repo là public. Runner tự host trên repo public là rủi ro nếu chạy mã không tin cậy. Workflow phase-testing.yml chỉ có workflow_dispatch và if: github.ref == 'refs/heads/main', nên không chạy mã PR/fork; giữ nguyên hai điều kiện này và không thêm trigger pull_request.
  • Máy runner không có đường mạng tới production (DB, Redis, S3, CVAT, VPS) và không giữ credential production.

3. Dịch vụ kiểm thử cô lập (trên máy runner)

  1. Tạo project Docker Compose riêng cho evaluation (tên project riêng, volume riêng, không dùng infrastructure/docker-compose.dev.yml), bind cổng vào 127.0.0.1 với cổng duy nhất.
  2. PostgreSQL: tạo role riêng được quyền tạo database test của pytest, không quyền trên database khác.
  3. Redis: một instance riêng cho broker và result backend (URL có thể khác số DB nhưng cùng instance riêng này).
  4. S3: tạo trước một bucket test, cấp credential chỉ cho bucket đó, từ chối mọi bucket production; dùng bucket không versioning hoặc đặt lifecycle xoá phiên bản cũ và delete marker.
  5. Ghi digest image từng dịch vụ vào inventory: docker image inspect --format '{{index .RepoDigests 0}}' <image>

4. Cài và đăng ký runner (người có quyền admin repo)

# Dưới tài khoản labelx-runner, thư mục riêng
mkdir -p ~/actions-runner && cd ~/actions-runner
# Tải bản runner từ trang GitHub; KIỂM SHA-256 trước khi giải nén
echo "<sha256-do-github-cong-bo>  actions-runner-linux-x64-<version>.tar.gz" | sha256sum -c -
tar xzf actions-runner-linux-x64-<version>.tar.gz

# Token đăng ký ngắn hạn: nhập ẩn, không đưa vào lịch sử shell hay repo
read -rs REG_TOKEN
./config.sh --url https://github.com/toilatrung/label-x --token "$REG_TOKEN" \
  --name labelx-evaluation-01 --labels labelx-evaluation --unattended
unset REG_TOKEN

# Chạy như dịch vụ hệ thống (cần sudo, thực hiện bởi người vận hành)
sudo ./svc.sh install labelx-runner && sudo ./svc.sh start
  • Runner có các nhãn self-hosted, linux (mặc định) và labelx-evaluation (thêm); khớp runs-on: [self-hosted, linux, labelx-evaluation] của workflow.
  • Giới hạn runner group chỉ cho repo này. Trong Settings → Actions → General kiểm tra chính sách workflow từ fork PR (yêu cầu phê duyệt cho mọi cộng tác viên ngoài).
  • Không đăng ký runner này cho repo/org khác.

6. Lệnh kiểm trên máy runner

# 6.1 Công cụ
python3 --version; node --version; uv --version; gh --version
# 6.2 Phụ thuộc khoá (từ checkout trusted main)
uv sync --frozen --project src/backend
# 6.3 Probe dịch vụ cô lập. Nạp biến từ tệp mode 0600, không bật set -x
export LABELX_EVALUATION_ISOLATED=true
export LABELX_TEST_NAMESPACE=ci-manual-1
set -a; . /path/to/private-0600.env; set +a
uv run --frozen --project src/backend python scripts/ci/evaluation-probe.py

Probe thực hiện: Postgres insert/read trong bảng tạm rồi rollback; Redis PING, SET/GET và DELETE đúng khoá; S3 bucket health và PUT/HEAD/GET/DELETE dưới namespace duy nhất. Đầu ra chỉ có tên kiểm tra, trạng thái và namespace; lỗi cleanup làm probe thất bại. Lưu JSON đã làm sạch cùng SHA commit và phiên bản công cụ.

# 6.4 Kiểm runner đã online và đủ nhãn (người có quyền admin repo)
gh api repos/toilatrung/label-x/actions/runners \
  --jq '.runners[] | {name, status, busy, labels: [.labels[].name]}'
# kỳ vọng: status "online", busy false, labels gồm self-hosted, linux, labelx-evaluation

7. Chạy thử và dọn dẹp

  1. Sau khi #390 hoàn tất, dispatch LabelX Phase Testing với một phase an toàn (ví dụ scaffold) trên main; workflow tự chạy kiểm environment, probe và pytest.
  2. Dọn sau run: chỉ xoá tài nguyên mang namespace/project của run; không dùng docker system prune, FLUSHALL hay xoá bucket dùng chung. Dọn workspace giữa các job.
  3. Xoay credential: tạm dừng dispatch, chờ job đang chạy xong, cấp credential mới, cập nhật secrets, chạy probe và một run có review, rồi thu hồi credential cũ.

8. Bằng chứng cần nộp để đóng #388

  • Inventory runner đã làm sạch: tên, trạng thái online/idle, nhãn, phiên bản runner, SHA-256 archive.
  • Inventory công cụ và digest image dịch vụ.
  • JSON kết quả probe PASS kèm commit SHA.
  • Cấu hình environment (reviewer, prevent_self_review, giới hạn nhánh), danh sách tên secret/variable (không giá trị).
  • URL một lần Phase Testing thật, artifact phase-evidence-<SHA> và xác nhận dọn dẹp.

Chưa có các mục trên thì #388 ở trạng thái NOT VERIFIED; không ghi failed khi chưa chạy.

9. Cần quyết định/cung cấp

  1. Máy riêng nào dùng làm runner và ai là người vận hành (cấu hình, SSH, token đăng ký).
  2. Có cần GPU cho các ca evaluation không (phụ thuộc checkpoint Detector và ca được chạy).
  3. Thêm LABELX_EVALUATION_ISOLATED vào acceptance của #390 (biến workflow đang bắt buộc).
  4. Chọn bản SeaweedFS (3.80 như CI hay 4.48 như smoke) cho dịch vụ S3 test.
