3. D04 — Rework read APIs

3.1 Danh sách

GET /api/rework/?dataset_id={id}&status={status}&cursor={cursor}

Tham sốKiểuBắt buộcQuy tắc
dataset_idinteger > 0CóDataset đang được người dùng chọn và có quyền truy cập.
statusenumKhôngfix_pending, recheck_pending, resolved, reopened.
cursorstringKhôngOpaque; chỉ dùng giá trị backend trả về.

Quyền đọc: Annotator chỉ thấy rework được giao cho mình. Reviewer/QA Lead/Super Admin thấy dữ liệu trong dataset scope. QC Admin chỉ được mở nếu RBAC matrix của backend xác nhận; T-042 không phụ thuộc quyền này.

Ngữ nghĩa counts: tính sau khi áp dụng dataset scope và quyền của người dùng, nhưng trước bộ lọc status. Nhờ vậy số trên các tab không đổi khi người dùng chuyển tab.

3.2 Chi tiết

GET /api/rework/{id}/

  • Response 200 là đúng một object có cùng schema với phần tử trong results.
  • Không bắt buộc gửi dataset_id; backend suy ra dataset từ Issue → FrameReview → Snapshot.
  • Annotator truy cập rework của người khác nhận 404 để không lộ sự tồn tại của bản ghi.
  • Vai trò hợp lệ nhưng không có dataset scope nhận 403. ID không tồn tại nhận 404.

3.3 TypeScript contract cho Frontend

export type ReworkStatus =
  | "fix_pending"
  | "recheck_pending"
  | "resolved"
  | "reopened";

export type ReworkSeverity = "critical" | "medium" | "minor";

export interface ReworkRead {
  id: number;
  dataset_id: number;
  issue_id: number;
  frame_id: number;
  annotator_user_id: number;
  created_by_user_id: number;
  status: ReworkStatus;
  instruction: string;
  severity: ReworkSeverity;
  original_revision: string;
  submitted_revision: string | null;
  recheck_run_id: number | null;
  due_at: string;
  cvat_deep_link: string;
  submitted_at: string | null;
  resolved_at: string | null;
  created_at: string;
  updated_at: string;
}

export interface ReworkListResponse {
  next: string | null;
  previous: string | null;
  results: ReworkRead[];
  counts: Record<ReworkStatus, number>;
}

4. D05 — Run lineage trong endpoint hiện có

GET /api/runs/{id}/

Giữ nguyên toàn bộ trường đang có của RunSerializer: id, snapshot_id, config_version_id, seed, status, is_final, origin_run_id, score_version, model_artifact, engines, created_by, created_at, finished_at. Bổ sung đúng hai trường sau:

{
  "verification_lineage": [
    {
      "verification_id": 55,
      "rework_id": 380,
      "recheck_run_id": 331,
      "outcome": "pass",
      "revision": "rev-0002",
      "verified_at": "2026-10-12T16:00:00+07:00"
    }
  ],
  "selected_final_sources": [
    {
      "cvat_job_id": 1,
      "rework_id": 380,
      "verification_id": 55,
      "source_run_id": 331,
      "source_revision": "rev-0002"
    }
  ]
}
TrườngNgữ nghĩaGiá trị rỗng
verification_lineageBằng chứng verify gắn với run. Với final run, lấy qua FinalRunVerification; với recheck run, lấy các ReworkVerification có recheck_run_id tương ứng.[]
selected_final_sourcesNguồn revision được final run chọn cho từng CVAT job, truy vết về rework và verification đã pass.[]
  • Origin run: origin_run_id = null, hai mảng có thể rỗng.
  • Recheck run: origin_run_id trỏ run gốc; lineage xuất hiện sau khi verification được tạo.
  • Final run: is_final = true; selected sources chỉ chứa nguồn có bằng chứng được final run chọn.
  • Quyền và dataset scope giữ nguyên RunDetailView: Reviewer, QA Lead, QC Admin, Super Admin.

6. Điều kiện nghiệm thu trước khi nối API thật

D04

  • List trả đúng scope, lọc đủ bốn status, cursor page 2 không trùng hoặc mất bản ghi.
  • counts giữ nguyên khi đổi status filter và phản ánh đúng quyền người dùng.
  • Annotator chỉ đọc bản ghi của mình; truy cập bản ghi người khác không làm lộ dữ liệu.
  • Detail có đủ instruction, severity, revision, run, timestamps và CVAT link.

D05

  • Origin, recheck và final run đều serialize được; mảng rỗng luôn là [].
  • Nhiều verification có thứ tự cố định; final source truy ngược được tới verification và rework.
  • Không thêm route /lineage/; OpenAPI của run detail thể hiện hai trường mới.
  • Contract test dùng fixture thật của M-03; Frontend manual test xác nhận Network payload khớp tài liệu.

Gate bàn giao

  1. Backend PR #226 xanh test và được review.
  2. OpenAPI/schema cùng fixture được cập nhật trong PR.
  3. Việt Anh chạy UI với API thật và lưu ảnh Network response cho D04 list/detail và D05 run detail.
  4. Chỉ sau ba bước trên mới ghi “T-042 đã tích hợp API”; trước đó ghi “FE prepared against proposed fixture — pending PO approval/backend merge”.
