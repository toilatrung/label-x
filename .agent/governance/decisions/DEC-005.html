Context

Rework tạo snapshot mới trên revision CVAT đã sửa, rồi QC run cuối (FR-RWK-03, FR-RWK-06). Issue thuộc một run, còn dedup_key (FR-AGG-03) chỉ có nghĩa trong một snapshot. Không có quy tắc nào nói một issue ở run cuối có phải là "cùng lỗi" với issue ở run gốc hay không, nên chưa thể nối verification cũ với kết quả run cuối (FR-RWK-06, FR-RWK-08). Đây là BLOCKER-007. Product Owner đã chọn phương án A trong DEC-002 ngày 2026-10-06; bản ghi này ghi phương án đó thành ADR với quy tắc đủ chi tiết để triển khai (E-01 scope; T-001).

Sự thật đã kiểm: CVAT giữ nguyên id của shape khi annotator sửa toạ độ, lớp hay thuộc tính; xoá rồi vẽ lại thì shape có id mới. Dự đoán Detector và vùng reviewer vẽ không có id CVAT. Frame của mỗi snapshot là bản ghi riêng, nhưng (task CVAT, số frame nguồn) không đổi qua snapshot (FR-SNP-05).

Decision Drivers

  • Truy vết được từng lỗi từ run gốc qua rework tới run cuối (FR-RWK-06; R-03).
  • Không tự kế thừa quyết định cũ cho kết quả mới: issue ở run cuối phải được review lại (FR-RWK-08).
  • Khớp tất định, tái lập được (R-01); không dùng ngưỡng hình học làm căn cứ chính.
  • Adapter CVAT chỉ đọc (B-18): không ghi id hay tag nào lên CVAT.

Decision Outcome

  • Rationale: Product Owner chọn A trong DEC-002 (BLOCKER-007). C hỏng đúng trường hợp rework; B chỉ đủ tin cậy để gợi ý.
  • Effective Date: 2026-10-07

Quy tắc

  1. Định danh frame qua snapshot: frame_key = (cvat_task_id, frame_number) (schema FrameKey trong openapi.yaml).
  2. Định danh đối tượng: ObjectRef = (namespace, id) với namespace ∈ cvat_shape (id shape CVAT), detector ("<run_id>:<index>", chỉ có nghĩa trong một run), reviewer_region (UUID do server cấp). Chỉ namespace cvat_shape ổn định qua revision.
  3. Khoá lineage của issue = (frame_key, nhóm lỗi, loại neo, tập ObjectRef namespace cvat_shape đã sắp xếp, rule_id nếu có). Neo theo DEC-006.
  4. Liên kết chính xác: khi aggregation của run is_final tạo issue có khoá lineage trùng một issue của run gốc (origin_run_id), hệ thống tạo issue mới ở pending_review và link recurrence_of → issue gốc. Issue mới không kế thừa quyết định, mức độ hay verification.
  5. Gợi ý fallback: issue không có khoá lineage chính xác (E1 neo vùng dự đoán; shape xoá rồi vẽ lại; cụm E3 chỉ trùng một phần) được so với issue gốc cùng frame_key và nhóm lỗi bằng IoU ≥ τm giữa bbox neo. Kết quả ghi link suggested_recurrence_of, chỉ hiển thị cho reviewer, không đổi trạng thái, gate hay KPI.
  6. Verification: issue gốc giữ trạng thái và verification của nó (vd resolved); run gốc giữ nguyên để kiểm toán (FR-RWK-06). Gate và báo cáo đọc issue của run cuối theo FR-RWK-08; điều kiện "rework bắt buộc verify 100%" tính trên yêu cầu sửa của run gốc.
  7. Lưu trữ: bảng issue_link(from_issue, to_issue, kind, method ∈ {exact, fallback}, created_at), UNIQUE (from_issue, to_issue, kind). Tạo link trong cùng transaction với upsert issue, nên retry aggregation không tạo link trùng (FR-AGG-02, FR-AGG-06).
  8. API trả link trong Issue.links (schema IssueLink); run cuối trả Run.origin_run_id.

Consequences

  • Positive: Truy vết đầy đủ lỗi qua rework cho E2, E3, cảnh báo cấu trúc và issue thủ công chọn object; gate/báo cáo không lẫn quyết định cũ với kết quả mới.
  • Negative: E1 và shape vẽ lại chỉ có liên kết gợi ý; reviewer phải review lại mọi issue tái xuất hiện ở run cuối; thêm bảng issue_link.
  • Follow-up Work: E-08 (aggregation tạo link), E-16 (rework + run cuối), E-11 (ranking không dùng link); bổ sung FR lineage vào SRS có version.
