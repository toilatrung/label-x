Các bước manual test

  1. Đảm bảo code backend/frontend đang chạy từ PRJ_Vin_DMS/label-x, nhánh local/gpu-worker-runtime. Cần khôi phục WSL trước nếu vẫn báo timeout, sau đó restart server từ đúng thư mục. Phiên này chưa chạy migrate/refresh vì chưa xác minh được instance đang chạy.
  2. Trên server Label-X: cài dependencies theo README, chạy uv run --frozen python manage.py migrate trong src/backend để apply migration mới. Thao tác này chưa chạy vào DB demo trong phiên triển khai.
  3. Cấu hình server .env: GPU_WORKER_ALLOWED_HOSTS là danh sách hostname Tailscale chính xác, phân tách dấu phẩy; GPU_WORKER_CREDENTIALS là JSON map alias → token. Không gửi token vào chat/Git. Token phải >=32 ký tự ASCII không có khoảng trắng. Restart backend và Celery sau đổi env.
  4. Trên máy GPU, từ root worktree: python scripts/worker/worker.py configure --checkpoint <đường-dẫn-checkpoint>, tiếp theo build, start, check. Token sinh trong .cache/gpu-worker/worker.env ngoài Git; chuyển qua kênh secret để khớp alias server. Chạy tailscale-command để xem lệnh Serve, tự kiểm tra grants/ACL rồi bật HTTPS trong tailnet; không dùng Funnel. Chi tiết trong README worker. Script chỉ quản lý project labelx-gpu-worker, không đụng stack dev của PR #346. Nếu port bận, thêm --port 8502 khi configure và dùng đúng port Serve.
  5. Đăng nhập admin toàn hệ thống → Configuration → Models và Guidelines → GPU Worker (/configuration/guidelines). Nhập tên/HTTPS URL, chọn alias, timeout; Lưu cấu hình rồi Kiểm tra kết nối. Mong đợi Sẵn sàng, Detector Đã nạp và xác minh, CUDA, model/version ánh xạ lớp/checksum và thời điểm kiểm tra thật. FE lấy các field sẵn có trong WorkerProbe/WorkerModel, không thêm API load model hoặc giả định có field classes trong response server. Tải lại cấu hình không nạp lại model. Kết quả là tại thời điểm probe, không phải monitoring liên tục.
  6. Đăng ký artifact bằng uv run --frozen python manage.py check_detector --register sau khi lưu worker remote. Lệnh verify manifest/worker, không cần checkpoint trên server; không overwrite artifact lệch. ConfigVersion mới phải bật detector và models trỏ đúng name/version đã đăng ký; không sửa config đã publish.
  7. Tạo run mới trên snapshot BDD100K locked. Kiểm tra detector checked, completed_units=eligible_units, failed_units=0; candidate có artifact_verified và checkpoint_sha256 đúng. Số candidate phụ thuộc ảnh/threshold, không dùng 48 của smoke cũ làm tiêu chí.
  8. Thử tắt worker/Tailscale, sai token, model khác hoặc worker dùng CPU: không được hiện Sẵn sàng và không được tạo run detector khi preflight thất bại. Nếu mất mạng sau khi run đã tạo, kiểm tra retry và trạng thái lỗi thực tế, không checked giả.
  9. Mở hai tab admin: lưu ở tab A, lưu revision cũ ở B phải báo lỗi; tải lại để tiếp tục. Đổi sang máy GPU khác đã allowlist: run mới dùng revision mới, run cũ giữ revision cũ. Giữ credential/host cũ cho tới khi các run đang chạy kết thúc.
  10. Kiểm tra giao diện ở 1440px và 390px, loading/error/empty, quyền reviewer và Quality Control Admin chỉ có scope dataset. API server vẫn chặn dù gọi trực tiếp.
