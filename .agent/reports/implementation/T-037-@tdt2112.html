Scope

  • Implemented:
    • Preserved delivered baseline from T-032 (#99 / PR111 auth/session) and T-034 (#101 / PR129 ReviewQueues, dataset/run selection, risk/random queues).
    • Integrated in-memory queue handoff in ReviewQueues: renders ReviewWorkspace inline inside the AppShell upon valid active grant, passing activeGrant.frame.id, activeGrant.lease, effectiveRunId, and datasetId without extra claim requests or query credentials.
    • Strict grant validation: checks frame.run_id === effectiveRunId, lease.frame_id === frame.id, holder_user_id === currentUserId, finite future expiry, and no conflict.
    • Context reset guards: dataset, run, or user changes immediately close workspace and clear active lease.
    • Completion callback: invalidates ranking cache and clears active lease.
    • Preserve view on expiry: lease expiry locks mutation actions via hook while keeping saved decisions and evidence visible in read-only mode.
    • Standalone route /review/workspace?frame_id=<id> operates in safe read-only inspection mode without fabricated lease credentials.
    • Mapped T-035 PR130 payload: GET /api/frames/{id}/issues/ image media, width, height, CVAT deep link, engine run statuses, pinned guideline, and issue anchors.
    • Frame payload validation: verifies frame.id === targetFrameId and frame.run_id === runId; mismatched payloads never render editable state.
    • Decision controls: implements the 4 direct actions (confirm, reject, uncertain, escalate). confirm validates that family strictly equals issue.family. Super Admin requires mandatory override_reason.
    • State machine enforcement (Follow-Up 18): only issue.state === 'in_review' can submit direct decisions. Non-in_review states (confirmed, rejected, escalated, resolved, pending_review, fix_pending) display informative callouts, lock form inputs, and strictly forbid POST decisions. Authoritative history (issue.review_decisions) is preserved across all states.
    • Save & Next navigation: "Lưu và chuyển issue tiếp ›" advances to next issue only after successful authoritative save and reconciliation; failed saves never advance.
    • PO Decision Compliance: request_fix is rendered disabled with clear T-040 atomic rework indication (per Issue #102 PO decision comment 6106568257) and is never dispatched to POST decisions.
    • 409 Conflict Differentiation: LEASE_CONFLICT invalidates lease, whereas INVALID_TRANSITION, IDEMPOTENCY_KEY_REUSED, and ISSUE_EXISTS do not invalidate lease and preserve saved decisions.
    • Canonical UUID Idempotency: generates RFC 4122 v4 canonical UUIDs for Idempotency-Key headers; reuses key on uncertain network retries.
    • Anchor Policy Resolution: resolveAnchorPolicy infers anchor-v1 from consistent server issues; locks manual creation on zero-issue frames or conflicting policies without hardcoded fallbacks.
    • Manual Issue Modal: enforces description ≤ 2000 chars, restricts objects to namespace: 'cvat_shape', validates finite in-bounds bboxes, and relies on server-allocated reviewer_region UUIDs. Unmount/context guards verify matching frame and lease IDs.
    • Role-based Snapshot Revision Lookup: eligible roles (qa_lead, super_admin) retrieve locked revision via GET /api/runs/{id}/ and GET /api/snapshots/{id}/; plain reviewer cannot access snapshot endpoint and is disabled with a clear notice without bypassing RBAC.
    • Design mock alignment (docs/design/screens/ReviewWorkspace.dc.html): added lx-head with context details and "Về hàng đợi" action, 3-step lx-flow navigation, lx-ws lx-ws--reference responsive grid, disabled frame navigation explaining queue-only lease handoff, dynamic findings title, annotation class (with honest gap notice), revision hash, and similar cases / lineage links details.
    • T-036 Effort Collector lifecycle adapter: implemented in useEffortCollector.ts consuming upstream ReviewEffortSession and EffortCollector; strictly binds positive integer user identity and grant holder, wraps storage access safely with per-user key (labelx:pending-effort-events:u${userId}:v1), triggers terminal loss of lease on actual expiry, preserves session across legitimate same-lease renewals, handles 409 LEASE_CONFLICT vs non-lease 409, and records transitions between view_frame and review_issue.

Actionable Contract Proposal for API Owner

Proposal: Include snapshot_revision: string directly in the FrameSummary schema (returned by GET /api/frames/{id}/issues/ and LeaseGrant.frame).

Rationale: POST /api/issues/{id}/decisions/ requires an exact snapshot revision SHA. Currently, this revision is only obtainable from GET /api/snapshots/{id}/, which is restricted to QA Lead / Admin roles. Including snapshot_revision on the frame allows plain Reviewers to submit decisions without granting broad snapshot inspection permissions.
