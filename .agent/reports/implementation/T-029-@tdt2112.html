Scope

  • Implemented (Phần độc lập đã hoàn thành trên develop):
    • Trang RulesThresholds (src/frontend/src/app/configuration/rules-thresholds/page.tsx) kết nối endpoint /api/config-versions/?status=published hiển thị cấu hình ngưỡng engine chỉ đọc.
    • Thành phần EngineThresholdsTable (src/frontend/src/components/execution/EngineThresholdsTable.tsx):
      • Xóa bỏ toàn bộ giá trị fallback giả định không được API trả về (không tự điền taxonomy version, tolerance, min area, IoU, detector confidence, model version, max candidates, hoặc enabled mặc định).
      • Nếu config thiếu engine hoặc params cần thiết, hiển thị rõ ràng: Chưa được cấu hình/không có dữ liệu từ API; tuyệt đối không tự suy ra engine đang bật.
      • Chỉ hiển thị cờ bật/tắt đã khai báo trong cấu hình khi API trả trường enabled kiểu boolean; nhãn không đại diện trạng thái runtime. Nếu thiếu trường, hiển thị Chưa khai báo.
      • Xử lý RBAC chuẩn xác: vai trò Reviewer có quyền xem guideline mappings nhưng không được xem cấu hình engine; giao diện hiển thị thông báo phân quyền rõ ràng, không gửi request trái quyền gây lỗi 403 âm thầm.
      • Xử lý lỗi API và trạng thái chưa có cấu hình phát hành bằng thông báo rằng không thể xác nhận ngưỡng từ dữ liệu hiện có; không suy luận trạng thái kiểm tra runtime từ việc thiếu config published.
      • Nhãn bật/tắt chỉ mô tả bản cấu hình published do API trả về; mỗi QC run gắn với config version riêng. runs/services.py lọc engine có enabled=false trước khi tạo WorkUnit.
    • Thành phần độc lập CandidateEvidenceList (src/frontend/src/components/execution/CandidateEvidenceList.tsx):
      • Được chuẩn bị trước độc lập theo đúng schema Candidate và Evidence trong contract.d.ts.
      • Không suy ra rawCount / dedupCount từ candidates.length.
      • Chỉ hiển thị callout số lượng khi parent truyền số liệu thực có nguồn rõ ràng; nếu chưa có API trả số liệu, không dựng callout số lượng.
      • Xóa khẳng định candidate “đã đưa vào Review Center” (trừ khi dữ liệu/API xác nhận trạng thái đó).
      • Empty state trung tính cảnh báo rõ "(không tự động xem là đạt kết quả)".
      • Xác nhận rõ trong mã và tài liệu: component chưa được kết nối vào ExecutionHistory và là phần chuẩn bị trước, chưa phải acceptance đã hoàn thành.
    • Bộ kiểm thử Vitest toàn diện: 15 test files (152 tests passed 100%), bổ sung test case chứng minh dữ liệu thiếu được biểu diễn là chưa biết/chưa cấu hình, không hiển thị giá trị mặc định giả và không phát sinh thông báo thành công giả; phân biệt rõ trạng thái chưa có dữ liệu/chưa kết nối với danh sách rỗng sau tải thành công.
  • Deferred / Blocked (Chưa hoàn thành & Đang bị chặn):
    • Chưa thể xác nhận chạy với backend develop cho /api/config-versions/: Mặc dù endpoint đã có trong OpenAPI baseline (docs/04-api/openapi.yaml), trên nhánh develop hiện tại, route backend DRF tương ứng CHƯA ĐƯỢC ĐĂNG KÝ (nằm trong PR #91/T-026 đang ở trạng thái draft). Do đó, phần UI này chưa thể được xác nhận chạy với backend develop cho tới khi route có thật. Tiêu chí “API thật” KHÔNG được đánh dấu hoàn thành chỉ dựa trên frontend test mocks.
    • Nối màn AnalysisConfig và ExecutionHistory: Hai màn hình này nằm trong PR #91 (T-026, draft) chưa merge vào develop. Nhánh T-029 tuân thủ nguyên tắc không đưa code chưa duyệt từ PR #91 vào nhánh.
    • Đọc danh sách Candidate/Evidence theo run: Xác minh OpenAPI hiện tại cho thấy GET /api/runs/{id}/ranking/ chỉ trả về RankedFrame (chỉ chứa rank, score, missing_evidence và số lượng issue theo family, không có chi tiết candidate/evidence). Để đọc candidate thật theo run, cần endpoint bổ sung (ví dụ GET /api/runs/{id}/candidates/).
    • Căn cứ governance cho thay đổi contract: Theo tài liệu AGENT.html điều khoản "Change Request Rule" (dòng 185–191), việc thay đổi contract bắt buộc phải có Change Request được approved. Chủ nhiệm task đã lập hồ sơ đề xuất CR-108 ở trạng thái proposed trình PO (@toilatrung) và QA/QC approver (@ducha180104) xem xét; giữ nguyên baseline OpenAPI và giữ tiêu chí này CHƯA HOÀN THÀNH khi CR chưa được duyệt.
