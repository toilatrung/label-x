M-FE01 — Hoàn thiện Frontend theo thiết kế

Milestone song song với M-02…M-05, thuộc R-001. Chờ phê duyệt CR-111 (nhánh tích hợp riêng develop-fe và tách phần frontend của epic). Chưa có task nào được phép bắt đầu khi CR-111 còn proposed.

Outcome

Toàn bộ 24 màn hình và component trong docs/design/screens/ có route và giao diện hoàn thiện, khớp thiết kế (skill labelx-design-fidelity), dựng song song với backend. Chức năng chưa có API vẫn hiển thị đủ giao diện, kèm cảnh báo Chức năng vẫn chưa được kết nối với server. Sau đó nối từng route vào API thật khi backend sẵn sàng (Phase 2).

Nhánh và cách làm

  • Nhánh tích hợp develop-fe tạo từ develop. Nhánh task feat/FE-xx-… tạo từ develop-fe; PR base develop-fe; comment Đã xem và duyệt theo CR-102.
  • Đồng bộ develop → develop-fe ít nhất mỗi ngày để không lệch contract và backend; chỉ PO merge develop-fe → develop sau khi review toàn luồng (labelx-flow-review).
  • Chỉ sửa src/frontend, docs/design khi cần thêm class vào Design System; không sửa backend, không đổi framework (DEC-001). Mọi PR phải qua skill labelx-design-fidelity và labelx-design.
  • Dữ liệu minh họa đặt trong lớp mock riêng (fixture lấy từ thiết kế, nhất quán 12,500 frame…), có nhãn Dữ liệu minh họa; thao tác ghi bị chặn, không gọi API giả.

Quy tắc

  • Ranh giới cứng giữ nguyên: adapter CVAT chỉ đọc; sửa annotation bằng deep link sang CVAT; quyền project/job kiểm ở API.
  • Epic chỉ EPIC_DONE khi cả backend và phần frontend (Phase 2) xong; milestone M-02…M-05 đo acceptance phần backend/API, phần màn hình thật theo dõi tại đây.
  • Task đang in-progress/review của epic có phần frontend giữ nguyên; phần frontend chưa bắt đầu chuyển sang FE-xx. Integrator rà soát và ghi bảng chuyển đổi vào task board.
  • Giao FE-xx cho nhiều developer để chạy song song; owner do PO gán khi duyệt CR-111.

Out of scope

  • Thay đổi backend, contract OpenAPI (nếu cần endpoint mới thì tạo CR/contract riêng).
  • Đổi stack hoặc thư viện UI chính.
